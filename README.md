# دبره · الحزمة الكاملة

منصة الترقية بالمهارة: مهاراثون 2026، المسار الأول، السؤال 1.2 «مسيرة للمستقبل».
الحزمة فيها الواجهة، وقاعدة البيانات، والـ API، وكل الأكواد اللي استُخدمت في البناء والفيديو، جاهزة للربط بقاعدة بيانات فعلية والنشر على Netlify.

## كيف تشتغل

- **وضع العرض (الافتراضي):** إذا `DABRAH_API_BASE` فاضي، المنصة تشتغل على البيانات التجريبية داخل الصفحة. هذا اللي تشوفونه في العرض.
- **وضع قاعدة البيانات:** إذا `DABRAH_API_BASE=/api`:
  - عند الفتح، المنصة تقرأ `GET /api/bootstrap`: الموظفين ومستوياتهم، والأوزان، والخطط، والسجلات.
  - كل تغيير (تحدي، شهادة، تسجيل، تدوير، خطة، تصويت…) يتحفظ في قاعدة البيانات.
  - الواجهة نفسها ما تتغير. الربط كله في «جسر قاعدة البيانات» داخل `src/template.html` (قسم v14).
- **التصحيح على الخادم:** الشهادات تتصحّح على الخادم من جدول الأسئلة، مو من المتصفح. تكلفة الخطط ودعم هدف تنحسب من جدول البرامج.

## النشر على Vercel (الحالي)

- `api/index.mjs` دالة Vercel وحدة تخدم كل `/api/*` (تستخدم نفس `netlify/functions/lib/routes.mjs`).
- `vercel.json` فيه أمر البناء، ومجلد `site`، والتحويلات، ورؤوس الحماية، والمنطقة `fra1`.
- متغيرات البيئة في Vercel (Settings ← Environment Variables):
  - `DATABASE_URL` = رابط Supabase من نوع Transaction pooler (المنفذ 6543).
  - `DABRAH_API_BASE` = `/api`
- كل push على `main` ينشر تلقائيًا.

## النشر على Netlify (خطوة بخطوة)

1. **أنشئوا قاعدة PostgreSQL** عند أي مزوّد (Neon أو Supabase أو غيرهم)، وانسخوا رابط الاتصال. أضيفوا `?sslmode=require` في آخره إذا ما كان موجود.
2. **أنشئوا الجداول وعبّوا البيانات التجريبية** من جهازكم:
   ```
   npm install
   DATABASE_URL="postgresql://…" npm run db:setup
   ```
   أو بدون Node: `psql "$DATABASE_URL" -f database/schema.sql` ثم `-f database/seed.sql`.
3. **ارفعوا المجلد كامل** على GitHub (بدون ملف `.env`)، واربطوه بموقع جديد في Netlify. الإعدادات تنقرأ من `netlify.toml` تلقائيًا.
4. **في Netlify:** Site configuration ← Environment variables، وعرّفوا:
   - `DATABASE_URL` = رابط القاعدة (سري).
   - `DABRAH_API_BASE` = `/api`
5. **أعيدوا النشر** (Deploys ← Trigger deploy). افتحوا `https://موقعكم/api/health`، ولازم يرجع `{"ok":true}`.
6. **افتحوا المنصة** وسجّلوا دخول. أي تحدي أو تسجيل يتحفظ، ويبقى بعد تحديث الصفحة.

> إذا تبون تنشرون وضع العرض بس (بدون قاعدة)، اتركوا `DABRAH_API_BASE` فاضي، والمنصة تشتغل مثل ما هي.

## التشغيل المحلي

- **الأسهل:** `npm install -g netlify-cli`، ثم `netlify dev`. يشغّل الموقع والدالة مع متغيرات `.env`.
- **بدون مكتبات:** إذا عندكم PostgreSQL و psql:
  ```
  createdb dabrah && psql -d dabrah -f database/schema.sql -f database/seed.sql
  python3 scripts/build-site.py
  PGURI="dbname=dabrah" node tools/dev-server-psql.mjs
  ```
  بعدها افتحوا http://localhost:8899
- **اختبار الـ API:** على قاعدة فاضية فيها schema و seed:
  ```
  PGURI="dbname=dabrah_test" node tests/api.test.mjs
  ```

## التعديل على المنصة

1. عدّلوا `src/template.html`.
2. `python3 scripts/build-site.py` يحقن الشعار ويضيف `env.js`، ويكتب `site/index.html`.
3. إذا غيّرتوا البيانات التجريبية: عدّلوا `database/seed.json`، وبعدها `python3 scripts/make-seed.py`.

## قبل البيانات الحقيقية (مهم)

- **الدخول تجريبي.** حاليًا أي أحد يختار دوره، والـ API يفترض إن الموظف هو عبدالله (`employeeId = 1`). قبل أي بيانات موظفين حقيقية:
  - اربطوا مزوّد هوية (مثل Supabase Auth أو Auth0 أو دخول المنشأة).
  - خلّوا الدالة تقرأ هوية المستخدم ودوره من الجلسة، مو من الطلب.
  - استخدموا جدول `app_users` جاهز للربط.
- **الصلاحيات حسب الدور:** الموظف يكتب على بياناته بس. المدير على فريقه. هيا على الخطط والأوزان. فيصل على الاعتمادات.
- **حماية البيانات:**
  - خلّوا القاعدة داخل المملكة إذا أمكن، والتزموا بنظام حماية البيانات الشخصية.
  - لا تخزنون هويات أو جوالات داخل نص التقارير. المنصة أصلًا تفحص هذا.
- **تقييم التقارير:** فحص التقرير حاليًا في المتصفح (8 معايير). للإنتاج انقلوه للخادم، أو اربطوه بنموذج ذكاء اصطناعي من الدالة نفسها.
- **سجل التراجع:** «تراجع» بعد رفض المقابلة يرجع الواجهة بس. أضيفوا نقطة إلغاء إذا احتجتوها.
